结果排布

现状是 O1：从最新一轮往前扫，列表编号倒着走（#12 → #2），与正文、与轨道刻度都相反。调研过一圈后，主流（Word 导航窗格、Acrobat / 预览的结果列表、VS Code 的按行结果、浏览器查找）都是文档序升序，并且从不给单条结果编号——编号留给"第几轮"这种绝对锚点，"我在哪"只由计数、高亮和刻度表达。O5 就是按这个结论做的：顺序恒定升序，就近交给定位，列表里不加提示行。

O5 就近定位 · 示意 锚点 = 距当前轮最近的命中（并列取更旧的一条）；打开时视口从锚点开始，它的上一行只露半行。

会话正文（背景示意）

把轨道贴合会话列边缘之后，命中项的落点仍然依赖滚动容器的偏移。缩进层级由 data-depth 标记，渲染时按最长前缀成组，分组内部不再二次排序。

索引构建分成若干空闲切片，每片不超过两毫秒，累计字符数达到阈值就让出主线程；扫描阶段同样切片，保证输入法组合期间没有抖动。

玻璃材质只换表面配方，尺寸与间距保持不变，因此三种材质之间切换不会引起重排，轨道刻度也不会跳动。

落点闪光由 Web Animations 驱动，`prefers-reduced-motion` 下整体关闭，滑动改用即时定位。
